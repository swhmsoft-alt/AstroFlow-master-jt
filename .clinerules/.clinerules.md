# 严格的 URL 与路径控制协议 / Strict URL & Path Control Protocol

## 🚨 核心红线 / Critical Red Lines
* **[中文]** 严禁在未经过用户明确调研和授权的情况下，自主设计、伪造、修改或调用任何网站/项目内的 URL 或文件路径。
* **[EN]** It is ABSOLUTELY FORBIDDEN to design, fabricate, modify, or invoke any website/project URL or file path without explicit prior research and user authorization.

## 1. 行为准则 / Behavioral Rules
* **[中文] 禁止捏造链接**：绝对禁止猜测、随意制定新的 URL 路由或更改现有 URL。
* **[EN] No Link Fabrication**: Never guess, arbitrarily create new URL routes, or alter existing URLs.
* **[中文] 重点防御内链**：禁止在项目内部链接（Internal Links）或页面跳转中伪造任何不存在的 URL 或路径。
* **[EN] Strict Internal Link Protection**: Do not fabricate non-existent URLs/paths in internal links or page redirections.

## 2. 强制执行机制 / Mandatory Enforcement Mechanism
* **[中文] 前置确认机制**：在需要新增或修改任何 URL/路径之前，必须向用户展示计划方案，并获得明确的同意后方可写入代码。
* **[EN] Pre-Approval Mechanism**: Before adding or modifying any URL/path, you MUST present the proposed schema to the user and obtain explicit approval before writing code.
* **[中文] 现有路由优先**：必须优先调研、检索和复用项目中已有的路由表或现有的目录结构。
* **[EN] Existing Route Priority**: You must prioritize researching, indexing, and reusing established route tables or existing directory structures in the project.
